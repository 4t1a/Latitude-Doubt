# Contributing to Latitude and Doubt

Thank you for your interest in contributing to **Latitude and Doubt: An exact ledger of meaning in messages**.

This repository serves as both the scientific record of the paper and a fully reproducible computational artifact. We welcome contributions that improve clarity, extend experiments to additional corpora or genomes, or fix discrepancies.

---

## Principles of this Repository

1. **Deterministic Reproducibility:** Every number, table, and figure in the paper must be generated by code. All pseudo-random processes must use fixed seeds.
2. **Data Integrity:** Raw datasets downloaded from public sources must match their cryptographic digests in [`data/CHECKSUMS.txt`](data/CHECKSUMS.txt).
3. **Mathematical Invariance:** Theoretical identities (e.g., $H(W, X) = I(W;X) + \mathrm{Lat} + \mathrm{Dbt}$) must hold to within floating-point machine precision ($< 10^{-14}$).

## Development Workflow

### 1. Setting Up

```bash
git clone https://github.com/4t1a/Latitude-Doubt.git
cd Latitude-Doubt

python -m venv .venv
source .venv/bin/activate   # On Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
pip install pytest ruff     # Development tools
```

### 2. Running Verification & Tests

Before submitting any changes, verify that the numerical identities pass:

```bash
python code/verification.py
python code/estimator_validation.py
pytest tests/
```

### 3. Modifying Experiments or LaTeX Sources

* If you modify any computational experiment in `code/`, re-run the pipeline to ensure that `data_out/` and `tables/` update consistently:
  ```bash
  python code/make_assets.py
  ```
* If you modify the manuscript (`main.tex` or `sections/*.tex`), verify that the PDF compiles cleanly without warnings or missing citations:
  ```bash
  make pdf
  ```

## Reporting Issues

If you identify a numerical discrepancy, a typo in the manuscript, or an environment incompatibility:
1. Check existing [GitHub Issues](https://github.com/4t1a/Latitude-Doubt/issues).
2. Open a new issue using our issue templates with details about your operating system, Python version, and dependency versions.

---

## Submitting Pull Requests

1. Fork the repository and create your feature branch (`git checkout -b feature/my-enhancement`).
2. Commit your changes with clear, descriptive commit messages.
3. Push to your branch and open a Pull Request against `main`.
4. Ensure all GitHub Actions CI checks pass.
